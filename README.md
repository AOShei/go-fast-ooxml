# go-fast-ooxml

Extracts Word, Excel and PowerPoint files (`.docx`, `.xlsx`, `.pptx`, their
macro and template variants, and Excel's binary workbooks, `.xlsb`) into
the shared go-fast document model,
[`gofastcore.Document`](https://github.com/AOShei/go-fast-core). Standard
library and go-fast modules only.

**Status: released as v0.2.0.** What changed in each release is in
[`CHANGELOG.md`](CHANGELOG.md).
What it promises about files from strangers is in [`SECURITY.md`](SECURITY.md).

| Format | State |
|---|---|
| Word | Text and structure are extracted: headings, list items with their computed labels, tables with merged cells, footnotes and endnotes with the numbers the document's settings and sections give them, comments, tracked changes, headers and footers, text boxes, pictures, embedded files, the data of charts and the text of SmartArt diagrams. Word's Horizontal Line, a shape the file marks as one, is a `thematic_break` in the body (not in a table, text box, header or note); a paragraph that only has a border is not one, and section, page and column breaks are layout and give no block. What the file declares about the display of text is kept (see below). With `Options.Spans`, bold, italic, underline, strike-through, superscript, subscript and links are reported as spans |
| Excel | Every sheet is a part; its cells are tables, with what each cell displays: numbers through their number formats, dates in ISO 8601, formulas as their stored results. Declared tables, pivot tables, merged cells, comments, drop-down lists, text in shapes, pictures, charts, chart sheets, SmartArt and embedded files are read. What the file declares about the display of text is kept (see below). Sheets are read in parallel. A binary workbook (`.xlsb`) gives what the same workbook as `.xlsx` gives, its formulas read back from their compiled form |
| PowerPoint | Every slide is a part, with the size of the slide. Its title is a heading and the slide's name; body text is list items with their bullets or numbers, or paragraphs; tables keep their merged cells; pictures, charts, SmartArt, speaker's notes and comments are read, and so is the text the layout and master put on every slide. Every block has its place on the slide. What the file declares about the display of text is kept (see below). Slides are read in parallel |

## How fast

Against the Python tools in use for these formats, each reading the same
file once in a process of its own, on one machine (a 12-core Ryzen 9
9900X). The table is generated by `bench/compare.py`; the corpus results,
the method and the versions are in [`bench/comparison.md`](bench/comparison.md).

The time for this library is the whole run of its command, writing text;
for the others it leaves out importing the library. docx2txt gives the
text of a Word file and none of its structure. In the library itself,
without starting a process, the three files take 0.03, 0.13 and 0.01
seconds with all workers, and 0.06, 0.58 and 0.05 with one.

With more than one worker (`Options.Workers`, all the CPUs by default), a
Word body or a sheet of 1 MiB or more is decompressed on a goroutine of its
own, ahead of its reading: 1.16 to 1.26 times as fast for such a file, the
larger the more. Under 1 MiB, where it would not pay, a part is read as
before. The document is the same with any number of workers
([`bench/README.md`](bench/README.md)).

On the 788 real files of the corpus, which include damaged, encrypted and
hostile ones, this library reads 773 and refuses 15 with a reason: seven
need a password, four are archives too damaged to read, and the rest are
other formats, a legacy `.xls`, a document type declaration and a cipher
other than AES. None makes it crash or hang. The same holds for 5,810 more
from other projects' test suites ([`bench/README.md`](bench/README.md)).

## Using it

```go
import (
    "github.com/AOShei/go-fast-core"
    "github.com/AOShei/go-fast-ooxml"
)

// The whole file as one document, in the model every go-fast library shares.
doc, err := gofastooxml.ExtractFile(ctx, "report.docx", nil)
doc, err := gofastooxml.Extract(ctx, readerAt, size, &gofastcore.Options{Spans: true})
fmt.Println(doc.Markdown())
```

`Extract` reads from anything that can be read at an offset (a file, bytes
in memory); the format is decided from the file itself, never from its
name. Options are `gofastcore.Options`; the settings only this library
has are fields of `Extractor` (`MaxCells`, `MaxArchiveMembers`,
`MaxSpinCount`), which implements `gofastcore.Extractor`. Errors wrap the
shared ones (`ErrMalformed`, `ErrUnsupported`, `ErrLimitExceeded`,
`ErrNoPartsSelected`, `ErrPasswordRequired`, `ErrWrongPassword`,
`ErrKeyRequired`). A file
that is damaged in part is not an error: what could be read is returned,
with warnings that say what could not.

- **Pictures are blocks.** Every picture is an `image` block with its
  place, its size and its alternative text, unless `Options.Images` is
  `ImagesNone`; `ImagesData` adds the bytes.
- **Symbol fonts are translated.** Text in Symbol, Wingdings, Wingdings 2,
  Wingdings 3 or Webdings is codes of the font, not letters: "ü" in
  Wingdings is a check mark. It is written as the characters Unicode gives
  those symbols, in all three formats, whether the font is set on the run,
  its style or the cell, and for bullets. A code Unicode has no character
  for (the Windows logo) is U+FFFD, and the part says how many with
  `text.unmapped_glyphs`.
- **A file cut short** has lost the directory at the end of its archive.
  Its members are then found by their own headers, as far as they go: a
  file that lost only its directory gives the whole document, one cut
  inside its body gives the body up to there. The document carries
  `input.repaired`, which says how many members were found and which one
  breaks off. Where too little is left to tell what the file is, the
  error is `ErrMalformed`.
- **A document holds at most `Limits.MaxTextBytes` of text**, 256 MiB by
  default, counted as often as it occurs and together with the files
  embedded in it. A small file can say a long text many times (one string
  that every cell refers to); the part that reaches the limit is cut off
  there with `limit.exceeded`. Every block counts 128 bytes besides its
  text, and every cell of a table 16, empty or not (core's `BlockCost` and
  `CellCost`): a file decides how many there are as freely as how long a
  string is. A table with no room for all its rows keeps those that fit.
  The targets of links count as text does,
  each time a link is written: one address may be linked to any number of
  times. An address is kept whole up to 8 KiB. The other limits are in
  [`SECURITY.md`](SECURITY.md).
- **What a fixed bound leaves out is said.** Besides the limits a caller
  sets, the reader keeps to fixed bounds, far beyond what Office writes:
  16,384 columns of a slide's table, 64 KiB of a field code, 16,384
  defined names, 1,024 series of a chart (the list is in `SECURITY.md`).
  A file that goes past one keeps what fits, and the part says what was
  left out with `limit.exceeded`, severity error, once for each bound,
  with how many: "table cells past column 16384 were not read (3 cells)",
  and for text cut short, how many bytes: "(2 names, 90 bytes left out)".
  Names and labels that reach the output (authors, names of sheets and
  shapes, a cell's stored value) are kept to 1,024 bytes and said the same
  way. What belongs to no part (sheets past the 65,536th, links to other
  workbooks, document properties) is said on the document.
  `limit.exceeded` is the only code for a cut, so its absence means
  nothing was cut.
- **An event every go-fast library can meet has the shared code.**
  Control characters removed, content of a kind not read, a supporting
  part or the document properties damaged, a formula with no stored
  result, a sparse area of a sheet written a row at a time, a file
  decrypted: `text.control_characters_removed`, `input.unread_content`,
  `input.stream_damaged`, `table.formula_no_value`, `table.region_split`,
  `input.decrypted` (go-fast-core v0.1.2). Only `ooxml.table_flattened`
  and `ooxml.integrity_mismatch` are this library's own.
- **A warning that could repeat is said once.** Parts that could not be
  read to their end, and drawings that name a chart or diagram the file
  does not have, are one `input.stream_damaged` warning each, with how many
  and the first eight: "12 parts could not be read to their end (a, b,
  …, and 4 more)". Core keeps at most 1,000 warnings on a part or a
  document and counts the rest in `warnings.omitted`.

**A part at a time.** `Open` gives a `File`, which reads a part when it is
asked for: the body of a Word document, a sheet, a slide.

```go
f, err := gofastooxml.Open("deck.pptx", nil)   // also OpenBytes, OpenReaderAt
defer f.Close()
f.Format(); f.NumParts(); f.Metadata(); f.Sheets()

for part, err := range f.Parts(ctx) {          // gofastcore.Part, in order
    ...                                        // nothing holds on to it afterwards
}
part, err := f.Part(ctx, 12)                   // one part, by number
doc, err := f.Document(ctx)                    // everything: what Extract returns
f.Warnings(); f.Children(ctx)
```

The parts are the ones `Extract` returns, each complete, with its warnings
and what the file declares about the display of its text. With more than one worker, up to four parts a
worker are read ahead, and each is handed on as soon as it and those
before it are read; what is held does not grow with the number of parts. A `File`
is safe for concurrent use, and each pass over it counts the limits afresh.

**A sheet too long to hold** is read a band of rows at a time:

```go
for band, err := range f.Rows(ctx, sheetNumber, 1000) {
    for _, b := range band.Blocks { ... }      // the tables of these 1,000 rows
}
```

Each band is a part like any other, with the sheet's number and name and
what the file declares about the display of its cells. Two million cells are read in 20 to 25 MB,
where the sheet read whole takes over 100 (`bench/README.md`). The price:
the sheet's part is read twice, a table that runs past the end of a band is
cut there and goes on in the next as a table marked `Continued`, declared
tables are not looked up, and comments, drop-down lists, shapes and
pictures are left to `Part`. Bands follow the order of the rows in the
file; a damaged file that gives its rows out of order has them sorted
within a band, not across bands. With more than one worker
(`Options.Workers`, all the CPUs by default) the sheet is decompressed on a
goroutine of its own, ahead of the reading of its rows: about 1.6 times as
fast, with the same bands.

## The command

```sh
go install github.com/AOShei/go-fast-ooxml/cmd/gofastooxml@latest

gofastooxml report.docx                      # the document as JSON
gofastooxml -format markdown deck.pptx       # or markdown, or text
gofastooxml -format text -exclude-display contract.docx
gofastooxml ./archive > documents.jsonl      # every Office file under a directory
```

JSON is written a part at a time, a sheet or a slide as soon as it is
read, and within a part a block at a time and a table a row at a time, so
the command holds about one part and not its encoding as well; the output
is the same bytes as for the document read whole. A workbook of 64 MB of
text (`poc-shared-strings.xlsx` in the corpus) peaks at 18 MB rather than
1.7 GB, `large.docx` at 43 MB rather than 110. Markdown and text are
written once the document is read.

| Flag | |
|---|---|
| `-format json\|markdown\|text` | What to print. JSON is the shared document; with several inputs each document is one line |
| `-o file` | Write there instead of standard output |
| `-parts 3`, `-parts 2-5` | Only those parts: sheets or slides by number |
| `-images meta\|data\|none` | Pictures: a block for each, with its place, size and alternative text (the default); their bytes too; or not at all |
| `-spans` | Bold, italic and the like, and links, as spans |
| `-exclude-display`, `-exclude-display=hidden` | In Markdown and text, leave out text the file declares not shown or drawn with no ink: all of it (also `=true`, `=all`), or what has the reasons named (`hidden`, `no_ink`, joined by `,` or `+`); `=false` or `=` leaves nothing out. JSON always has everything |
| `-furniture`, `-part-markers` | In Markdown and text: include running headers and footers; put a line before each part saying which it is |
| `-stored`, `-stored=field_code,macro` | In Markdown and text, include what the file stores and shows nowhere: all of it (also `=true`, `=all`), or only the kinds named (joined by `,` or `+`; see [What a file stores](#what-a-file-stores-and-shows-nowhere)); `=false` or `=` leaves it out |
| `-children` | In Markdown and text, the documents a file embeds, each after a line naming it (`[child 1: book.xlsx]`); on by default, `-children=false` leaves them out |
| `-workers n` | Sheets or slides read at a time |
| `-max-cells n`, `-max-decoded-bytes n`, `-max-text-bytes n` | The limits; `-1` for none |
| `-password p` | The password of an encrypted file, and of encrypted files embedded in it |
| `-key file` | A private key (RSA; PEM or DER, PKCS #1 or #8) for a file encrypted for its certificate, and for encrypted files embedded in it; may be given more than once. An encrypted key file is not read |
| `-max-spin-count n` | Rounds of hashing an encrypted file may ask for when a password is tried |
| `-quiet`, `-version` | |

Only documents go to standard output. A file that cannot be read is
reported on standard error and makes the exit status 1; the other inputs
are still read. Unless `-quiet` is given, a line on standard error names
the files that have a warning of severity error. Office
files embedded in a document are extracted too, into its `children`.

## Encrypted files

A file encrypted with a password is opened with `Options.Password`:

```go
doc, err := gofastooxml.ExtractFile(ctx, "accounts.xlsx", &gofastcore.Options{Password: "..."})
```

Both ways Office has of encrypting with a password are read: the one of
Office 2007 ("standard": AES, SHA-1), which LibreOffice still writes, and
the one of Office 2010 and later ("agile": AES-128, 192 or 256 with SHA-1,
SHA-256, SHA-384, SHA-512 or MD5). The document is the one the file would give
unencrypted, with `Metadata.Encrypted` set and an `input.decrypted`
warning that names the scheme and what opened it.

- **The password is verified before anything is decrypted.** Without one
  the error is `ErrPasswordRequired`; with one that does not open the file,
  `ErrWrongPassword`.
- **Excel's own password is tried without being asked for.** A workbook
  that is protected, but has no password to open it, is encrypted by Excel
  with a fixed password that Excel itself tries silently. Such a file
  opens with no password given, and the warning says that is how.
  `Metadata.Encrypted` is set all the same: it says what the file was,
  not who supplied the password.
- **Nothing is held decrypted.** The package is decrypted piece by piece
  as the parts are read, also from several workers at once.
- **A file that was changed after it was encrypted says so.** The agile
  scheme stores a keyed hash of the encrypted file; where it does not
  match, the document carries `ooxml.integrity_mismatch`, and is extracted
  all the same.
- **What a wrong guess costs is the file's to say**, as rounds of hashing:
  Office writes 100,000, about a hundredth of a second. `Extractor.MaxSpinCount`
  bounds it (a million by default); a file that asks for more is refused
  with `ErrLimitExceeded`. The check stops when the context is cancelled.
- An encrypted file embedded in a document is opened with the same
  password; if that does not open it, it is listed with `child.encrypted`.
  A document and everything embedded in it share one allowance for
  password checks, ten times `MaxSpinCount`, so that a document with
  thousands of encrypted attachments cannot cost thousands of checks; past
  it, further encrypted files are listed with `child.failed` and the
  reason.

**Encrypted for a certificate.** The agile scheme can encrypt the file's
key for certificates as well as for the password: whoever has the private
key of one opens the file without the password. Such a file is opened with
the key in `Options.Keys`, a `crypto.Decrypter`, so the key may be kept in
hardware or in another process:

```go
doc, err := gofastooxml.ExtractFile(ctx, "board.docx", &gofastcore.Options{Keys: []crypto.Decrypter{rsaKey}})
```

- A key is tried on the certificates whose public key is its own, and the
  file's verifier for the certificate is checked before anything is
  decrypted. The keys are RSA, the only kind the scheme uses. A key costs
  no rounds of hashing, and is tried before any password.
- The `input.decrypted` warning names the certificate that opened the
  file. Opened with the password, it says what certificates the key is also
  encrypted for.
- Opened with neither, the error wraps `ErrKeyRequired`, beside
  `ErrPasswordRequired` or `ErrWrongPassword` when the file can also be
  opened with a password, as the specification requires of every file. The
  message names the certificates (at most three).
- No file encrypted for a certificate by Office was at hand. The reader
  follows the published specification ([MS-OFFCRYPTO] 2.3.4.10), and is
  tested against an encryptor written for the tests from the same text.
  The specification does not say how the key is padded for RSA: PKCS #1
  v1.5, which Office's cryptographic interface gives by default, is tried
  first, then OAEP; the verifier decides. A mistake in this reading shows
  as a refusal, never as wrong text, because the verifier and the
  integrity check both fail on a wrong key.

**Not read:** files protected by rights management, ciphers other than
AES, and the legacy binary formats
(`.doc`, `.xls`, `.ppt`), which share the container of encrypted files:
each is refused with `ErrUnsupported` and a message that says which it is.
A file protected by rights management cannot be read here at all: its key
is in a licence that a rights-management server issues to the people the
document names, and this library contacts no server. The message says so,
and an embedded one is listed with `child.unsupported` and the same
message.

## Excel workbooks

**Cells are given as displayed.** A cell holding 1234.5 with the format
`#,##0.00` is `1,234.50`; 0.125 as `0.0%` is `12.5%`. The number-format
engine (`internal/numfmt`) handles sections for negative numbers, zero and
text, conditions, thousands and scaling, percent, scientific and
engineering notation, fractions, durations, currency and literal text. It
agrees with LibreOffice on all 6,048 pairs of a table of formats and
values, and on the cells of 446 real workbooks (see `bench/README.md`).

Four things are not as displayed, on purpose:

- **Dates and times are in ISO 8601** whatever the format: `2026-03-04`,
  `2026-03-04T14:30:00`, `14:30:00`. `03/04/2026` is two different days
  depending on where the file was made. What is written follows the value,
  so nothing it holds is lost: a cell formatted to show only the date still
  gives its time of day if it has one. Durations (`[h]:mm`) are not dates
  and are given as displayed.
- **General numbers keep all fifteen digits** a spreadsheet stores. Excel
  shows a number of twelve digits or more in scientific notation; an
  account number should not become `1.23457E+11`.
- **Padding is one space.** Formats can ask for blank space as wide as some
  character, or for a character repeated to fill the cell. Neither is
  reproduced.
- **A value its format displays as nothing is written out**, with the
  reason `hidden`, except zero: formats blank zeros as a matter of
  course.

A formula gives its stored result. Formulas are not evaluated, and one
stored without a result is an empty cell, reported as
`table.formula_no_value`.

**What a cell holds besides its text** is in `Table.Cells`, an entry for
each cell that has something:

- with `Options.Spans`, where the cell links to: an address, or `#` and a
  place in the workbook;
- with `Options.Cells`, its formula as Excel shows it, without `=` (a
  formula a range of cells shares is moved to each cell, as Excel moves
  it), and the type of its value (`number`, `date`, `bool`, `error`,
  `text`) with the value where the text does not show it in full: 0.333 in
  a cell showing `33%`, a date's serial number. Across the 30,144 formulas
  and 1,326 links of the corpus's workbooks, these agree with openpyxl's
  (`TestExcelCellDetailsAsOpenpyxl`); openpyxl leaves out spaces some
  shared formulas have, which are kept here. On a sheet of numbers there
  is an entry for every cell: `large.xlsx` takes about half as long again
  to read with `Cells`, and allocates three times as much.

Markdown writes the links of cells; formulas and values are only in the
document, since a formula can hold text nobody sees on the sheet.

**What a workbook stores and shows on no sheet** is in a last part of
kind `stored`: its defined names (`Rate: 0.2`; a name
can stand for a text that appears nowhere else), the code of its Excel 4
macro sheets, one formula to a line, the code of its VBA project, the
records of pivot caches whose source is gone and the formulas of
calculated fields, and custom XML data (see
[What a file stores and shows nowhere](#what-a-file-stores-and-shows-nowhere)).
It is read as data, never evaluated, and comes with the whole document,
not with a range of parts.

**Drop-down lists** (data validations of type list) are `note` blocks of
type `choices` at the cells they are for, with those cells in `loc.range`:
the values of a list written out in the file, one per line, or the
reference a list is taken from (`=$D$1:$D$3`, `=Lists!$A$1:$A$12`), since
those values are in the text of their cells. A list whose arrow the file
hides, or whose cells are all in hidden rows or columns, has the reason
`hidden`. Both the older kind and the newer kind kept in the sheet's
extension list are read. The 56 lists of the corpus's workbooks agree with
openpyxl's (`TestExcelDropDownListsAsOpenpyxl`); openpyxl does not read
the newer kind. Other kinds of validation offer nothing to choose from and
are not read.

**Tables.** A table the workbook declares is one table block, with its
header row. The other cells are grouped into blocks separated by empty rows
and columns; those boundaries are a reading of the layout, so such tables
have `origin: inferred`. Every block has its place on the sheet in
`loc.range`. An area whose cells are so scattered that the rectangle around
them is nearly all empty is written as one table per run of adjacent cells,
with `table.region_split`. A table of more than about a million cells is
written as several, each a run of its rows.

**Limits.** Besides the limits of `gofastcore.Options`, `Extractor.MaxCells`
bounds the cells kept from a workbook (20 million by default), and the text
of the cells is bounded by `Limits.MaxTextBytes`, counted each time it is
used: a long string that a million cells refer to is small in the file and
large in the result. A sheet that reaches a limit is cut off there, with
`limit.exceeded`.

A chart's table is not cells of the sheet: its `loc.range` is the cell the
chart is anchored to, and its role is `chart` (see
[Charts and SmartArt](#charts-and-smartart)). A chart sheet is a part with
no cells; its chart's blocks have no `loc.range`.

**Pivot tables.** A pivot table is the cells it fills, written when it was
last laid out: they are read as one table, like a declared table, with the
pivot table's name and `role` `pivot`, its header rows those above its
first row of values. A pivot table that is laid out only when the file is
opened has no cells yet, and gives no table. A pivot table is drawn from a cache, the records of its
source kept in the workbook. Where the source is a range or table of the
workbook, the records repeat cells that are read and are not read again.
Where it is another workbook, a connection to a database, scenarios, or a
sheet or name the workbook no longer has, the records are data the file
holds and shows nowhere: they are a table in the stored part, with
`stored` `pivot_cache`, the names of the cache's fields
as its header row and a row for each record (or, for a cache that keeps no
records, the values each field takes, a column each). Over the corpus and
the soak set, every pivot table openpyxl finds whose region has cells is
such a table, and every cache whose source is gone is in the stored part
with its fields and its number of records (`TestPivotsAsOpenpyxl`,
`GOFAST_PIVOTS_SOAK=1` for the soak set).

**Binary workbooks (`.xlsb`).** Excel's binary format is the package of an
`.xlsx` file whose workbook, sheets, shared strings, styles, comments and
tables are records ([MS-XLSB](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xlsb/)) in place of XML; its theme, drawings and
charts are XML as in `.xlsx`. The records are read into what the XML
gives, so formats, dates, tables, display reasons, limits and reading by
bands are the same code for both: the same workbook written both ways
gives the same document (`TestXlsbAsXlsx`). The source's `format` is
`xlsx`, its `mime` that of `.xlsb`.

Formulas in this format are compiled: tokens in reverse Polish order,
functions by number. They are turned back into the text Excel shows:
cells' formulas (with `Options.Cells`), defined names, drop-down lists,
the code of macro sheets and the calculated fields of pivot caches. That
includes references to a table's columns by name (`Sales[Amount]`,
`Sales[[#This Row],[Amount]]`, `Sales[#All]`), to other workbooks by the
number of their link (`[1]Rates!A1`, `'[1]Q 2'!A1`, `[1]!Tax`), the
functions of add-ins by the name the workbook lists, and the functions and
commands of Excel 4 macro sheets (`GET.CELL`, `ALERT`), whose names are
those of the specification's tables. A formula that still cannot be read
back is left out and counted in `input.unread_content` ("binary formulas
not read back"): wrong text would be worse than none. That is one through
a DDE or OLE link, or that names a table, column, sheet or name the
workbook does not have.

How this is checked:

- Each feature is written as a workbook in both formats, and the two
  documents are compared whole (`TestXlsbAsXlsx`, `TestXlsbFormulasAsXlsx`,
  `TestXlsbPivotsAsXlsx`).
- Over the binary workbooks of the soak set, every cell pyxlsb reads holds
  the same here (905 cells, `TestXlsbAgainstPyxlsb`).
- Every formula read back is the one LibreOffice writes when it saves the
  workbook as `.xlsx` (324 formulas, `TestXlsbFormulasAgainstLibreOffice`).
  The exception is one reference to a workbook whose path the file
  records as missing: `[1]ab!C1` here, `#REF!` in LibreOffice.
- LibreOffice reads the test workbook's references to other workbooks
  with the same text, and resolves each reference to a table's columns to
  the same table, rows and columns, though it writes them as ranges of its
  own (`TestXlsbFormulasAgainstLibreOfficeToo`).
- LibreOffice reads neither another workbook's names nor the functions of
  macro sheets, so those two are checked against the specification only.

The pivot tables of the three soak-set workbooks that have them have the
same names and places as in LibreOffice's `.xlsx`, except one that
LibreOffice lays out again. Their calculated fields have the same
formulas, except that LibreOffice quotes every field's name.

**Not read:** dialog sheets (counted in `input.unread_content`), and the
formulas of a pivot table's calculated items. Macro sheets and VBA
projects are reported as `input.active_content`, and their code is read
as text, never run.

## PowerPoint presentations

**One part per slide**, in the order of the presentation, hidden slides
included. `Width` and `Height` are the size of the slide in points, and
every block that comes from a shape has `loc.bbox`: the shape's box on the
slide, after the groups it is in have moved, scaled, turned and mirrored
it. A placeholder that does not say where it is has the place of the
placeholder it takes after, on the layout or the master.

| On the slide | In the model |
|---|---|
| Title | `heading` level 1, and the part's `Name`. A title of several paragraphs is one heading |
| Subtitle | `heading` level 2 |
| Body text and text boxes | `list_item` where the paragraph has a bullet or a number, with its level, and the bullet or the number as shown in `Marker` (`•`, `3.`, `b)`, `IV.`); `paragraph` where it has none |
| Table | `table`, with merged cells, and the first row as header where the table says it is one |
| Picture | `image`, with its description as text, unless `Options.Images` asks for none |
| Date, footer and slide-number placeholders | `footer`. A slide-number field shows the slide's number |
| Text the layout or the master has of its own | `header` if it is in the upper half of the slide, `footer` if in the lower; on every slide that shows it, once where layout and master repeat each other |
| Speaker's notes | `note` blocks of type `speaker`, one for each paragraph |
| Header and footer of the notes pages | `header` and `footer` blocks after a slide's notes: the notes page's own, or the notes master's, with the master's own text. A header or footer the master switches off (`p:hf`) has the reason `hidden`. The date and the page number are not read |
| Header and footer of the handouts | `header` and `footer` blocks from the handout master, once, after the first slide |
| Comments, in both the older and the threaded form | `note` blocks of type `comment`, with author and date; replies follow the comment |

Whether a paragraph has a bullet, how large its text is and what colour it
has are often not said on the slide: they come from the placeholder on the
layout, from the one on the master, from the master's style for that kind
of text, or from the presentation's defaults. All of those are read. The
"Click to edit" text of the placeholders on layouts and masters is not on
any slide and is not extracted.

**Reading order.** Shapes are stored in the order they were drawn, not the
order they are read in. The blocks of a slide are given title first, then
from the top down, and from left to right among shapes that start beside
each other. A group is read as one thing, at the place of the group. Shapes
that lie wholly outside the slide come after those on it, then the layout's
and master's text and pictures, the notes and the comments. The order is a reading of
the layout; what each block is and where it ends are declared, so blocks
stay `origin: native`.

**Limits.** `Extractor.MaxCells` bounds the cells of tables as it does for
workbooks. The text of a master is on every slide that uses it, so a long
master and many slides can ask for much more than the file holds: at most
about a million blocks are repeated in this way over a presentation, and a
slide past that says so with `limit.exceeded`. What a limit leaves out is
the same for any number of workers.

**Not read:** sound and video clips, counted in `input.unread_content`;
animations. An action that starts a program or
runs a macro is reported as `input.active_content` and never run.

## Charts and SmartArt

The same in all three formats.

**A chart** is its data, as the chart's cache holds it: a `caption` block
with its title, then a `table` block with `role` `chart`, the chart's
type in `chart` (`bar`, `line`, `pie`; several, space-separated, for a
chart that combines them; the newer kinds by their layout: `waterfall`,
`sunburst`, `treemap`, `funnel`, `boxwhisker`, `clusteredcolumn` for a
histogram), its name in `name`, and the titles of its axes in `x_axis` and
`y_axis`. The header row has the names of the series; the first columns,
with an empty header, the categories, outermost first; then a column of
values for each series, written through their number formats as the
chart labels them (a date as a date, in ISO 8601). A bubble chart has a
second column for each series, the sizes of its bubbles. Series that do
not share their categories, such as those of a scatter chart, are tables
of their own. A title with no text of its own is the name of the chart's
one series, as Office shows it.

- The cache is what the chart was drawn from when the file was saved. The
  workbook a chart in Word or PowerPoint embeds is handed to
  `Options.Child` as an embedded file: it may hold more than the chart
  shows. Excel keeps the data of its newer charts on the sheet and none in
  the chart: such a chart's table has the names of its series only.
- **Series a chart's filter leaves out** are in the file, declared not
  drawn: they are read, in a table of their own with the reason `hidden`.
- A chart holds at most about two million points; a larger one is cut off
  with `limit.exceeded`.
- Across 1,413 series in the corpus and the soak set, the names,
  categories and values agree with python-pptx and openpyxl
  (`TestChartsAsOracles`).

**A SmartArt diagram** is the text of its data model, in the order and
nesting the model declares: a `list_item` for each paragraph of a node,
its level the node's depth. Office also keeps the drawing it made of the
diagram; where the file has it, each item has the place of the shape it
is drawn in (on a slide), and what the drawing declares is kept: a shape
marked hidden, text drawn with no ink. A node the layout draws nowhere is
in the file and on no slide, but nothing in the file switches it off: it
is an item with no reason, like any other. A drawing that is
empty, or draws none of the model, is out of date and is not used.
Text on the connectors between nodes (an arrow's label) is an item
between the nodes it joins. Against LibreOffice, which imports the
drawing, over the 111 presentations with SmartArt in the corpus and the
soak set, all 961 diagram paragraphs it shows are in this library's text
(`TestSmartArtAsLibreOffice`, `GOFAST_SMARTART_SOAK=1` for the soak set).
Where a diagram has no drawing, LibreOffice lays the model out itself and
may leave text out; that text is given here.

## What a file stores and shows nowhere

A file can keep text that nobody who opens it sees. All of it is read as
data, never run or followed, and bounded by the limits. What belongs to
the file as a whole is in a last part of kind `stored`, which comes with
the whole document, not with a range of parts; each block says what it
is in `stored`. Word's field codes stay where their fields are, in the
body or a header or footer, marked `stored` all the same. The renderers
leave out the stored part, and every block marked `stored` wherever it is,
unless `RenderOptions.Stored` is set, or `RenderOptions.StoredKinds` names
its kind; a consumer can keep stored data from a model, or review it, by
its kind.

Being stored says where the text comes from. It sets no display reason:
the file declares nothing about the display of such data, and its length
is not judged.

| `stored` | What |
|---|---|
| `macro` | The code of a VBA project, in all three formats: a `code` block for each module, `language` `vba`, `name` the module's. Decompressed as [MS-OVBA] describes, and decoded from the project's code page: the Windows code pages 874, 932, 936, 949, 950 and 1250 to 1258, Mac Roman, ISO 8859-1 and UTF-8, from Microsoft's tables of them. A character a code page does not define, or text in another code page, is U+FFFD, counted by `text.unmapped_glyphs`. All 246 modules of the corpus and the soak set are the same as olevba's (`TestMacrosAsOlevba`, `GOFAST_MACROS_SOAK=1` for the soak set). In Excel also the formulas of Excel 4 macro sheets, `language` `excel4` |
| `custom_xml` | Custom XML data with text, in all three formats: a block for each part, a line for each element with text of its own (`Abstract: …`). Attribute values are not read. Data a content control is bound to is also in the body, where the control shows it |
| `document_variable` | Word's document variables, `name: value` |
| `defined_name` | Excel's defined names |
| `pivot_cache` | The records of an Excel pivot cache whose source is gone, as a table, and the formulas of calculated fields (`Margin: =Sales*0.1`) |
| `field_code` | Every code of a Word field: a `note` of type `field` after the paragraph its field ends in (see below) |
| `after_end` | Data appended after the end of the zip archive, where Office stops reading: its text, if it is text (UTF-8), up to 1 MiB. The stored part also carries `input.trailing_data`, which says how many bytes follow the end, whatever they are |

**Field codes** in Word are the instructions of fields, whose results are
the text: a page number (`PAGE`), a cross-reference, a table of contents,
a merge field, an index entry (`XE "…"`), the branches of `IF`, a citation
tool's data (`ADDIN`). The result is text where the field is. The code is
never shown, and every code is kept, whatever the field: a `note` block of
type `field` after the paragraph its field ends in, marked `stored`
`field_code`, so that rendered text has the results and not the codes
unless `RenderOptions.Stored` is set. A code has no display reason of its
own; one in a header or footer the document switches off takes the
header's or footer's. A field in another's code is written into that code
in braces, as Word shows it (`IF { MERGEFIELD Title } = "Dr" …`), and its
result, which nothing shows, is not text. An equation field (`EQ`) and a
macro button (`MACROBUTTON`) show their codes' text.

## Equations

Equations in Word and PowerPoint are written in UnicodeMath, the linear
form Word shows when an equation is switched to linear (Unicode Technical
Note 28): `x=(-b±√(b^2-4ac))/(2a)`, `∑_(k=0)^n▒((n¦k)x^k a^(n-k))`,
`lim┬(n→∞)⁡a_n`, `■(a&b@c&d)`. Every character of the equation is kept, in
order. A Word paragraph that is a display equation and nothing else is a
`formula` block with `notation` `unicodemath`; an equation in a sentence
stays in the sentence.

## What the file declares

Everything a file holds is extracted. Where the file itself declares that
text is not shown, or that it is drawn with no ink, the block says so in
`Display` (JSON `display`), as go-fast-core defines it (its README, "What
the file declares"). This library reports declarations and nothing else:
it does not judge whether a reader could see the text, or whether it is
harmful, and a block with no reason says nothing about either. Threat
detection is outside this library.

| Reason | Meaning |
|---|---|
| `hidden` | The file switches the content off |
| `no_ink` | The file declares the text drawn with no paint |

A declaration is one switch or one value, found by following the file's
own inheritance (a style, a placeholder, a master). Nothing that needs two
values compared or a threshold is reported: not colour against what is
behind it, not text size, not a place off the page or slide, not a box too
small for its text, not a shape over the text, not conditional formatting.

What is reported, by format:

| Format | `hidden` | `no_ink` |
|---|---|---|
| Word | Hidden text (`w:vanish`, `w:specVanish`), on the run or through its character style, its paragraph's style or the document defaults; hidden text and a hidden paragraph style cancel, as in Word. A footnote, text box or picture anchored in hidden text. A drawing whose `wp:docPr` is `hidden`, a legacy shape whose style says `visibility:hidden`. A header or footer the document's own settings switch off: a first-page one where no section has a different first page, an even-page one where the document does not have different odd and even pages. (A header or footer part that no section names is used by nothing, and has no reason.) | A Word 2010 text fill (`w14:textFill`) of nothing, or fully transparent |
| Excel | A hidden or very hidden sheet: the part and all its blocks. Hidden rows and columns, filtered rows among them. A value its number format displays as nothing (`;;;`), other than zero. A shape or picture marked hidden; the hidden stand-in Excel writes for a form control kept in the legacy drawing is not one. A drop-down list whose arrow is hidden or whose cells are all hidden. The series a chart's filter leaves out | Shape text with no fill, or a fill of zero opacity |
| PowerPoint | A hidden slide (`show="0"`): the part and all its blocks, its notes included. A shape or group marked hidden. Text in a table cell that a merged cell covers. A notes or handout header or footer the master switches off (`p:hf`). The series a chart's filter leaves out | Text with no fill and no outline, or a fill of zero opacity, through the run, its level, the placeholders it takes after, the master's styles and the presentation's defaults |

Where only part of a paragraph has a reason, a span over that part carries
it; in a table, regions of cells do (`table.display`), cells side by side
or one under another with the same reasons making one region, so a hidden
column is one entry however long it is. A part's reason (a hidden sheet or
slide) is on all of its blocks. `RenderOptions.ExcludeDisplay` leaves the
text with the reasons named out of rendered output; by default it is in.

Characters that display as nothing (Unicode tag characters, bidirectional
controls, zero-width characters, variation selectors) are kept in the text
as the file has them, with no reason.

Content shown on no page but extracted by design has its own place in the
model, and no reason for that: document properties, alternative text of
pictures, comments, speaker's notes, the values of drop-down lists, field
codes, and what the file stores (see above). Formulas, with
`Options.Cells`, are in `Table.Cells`, apart from what cells show.

**Not extracted at all:** in Excel, the records of a pivot cache whose
source is in the workbook (they repeat its cells), and the formulas of a
pivot table's calculated items; in Word, the building blocks of its
glossary document; in PowerPoint, the tags that add-ins store on slides
and shapes; attribute values of custom XML data.

## Running the tests

```sh
go test ./...
```

Tests that need LibreOffice, pandoc, the Python comparison tools or the
downloaded corpus skip themselves when those are absent. To run everything,
see `bench/README.md` and `python3 testdata/fetch.py`.

```sh
python3 testdata/soak.py && go test -run TestSoak -v .   # 6,598 files, under a minute
go test -run 'Budgets' -v -speed .                       # allocation budgets and the speed targets
```
